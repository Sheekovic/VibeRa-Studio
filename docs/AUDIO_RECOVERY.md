# Audio recovery and failed graph preparation

Development investigation2026-10-14. These are original changes against the pinned JUCE/Tracktion foundation. They do not establish complete real-time safety, FL parity, hardware deadlines or listening acceptance.

## Continue DSP after a transient overload

The pinned Tracktion `DeviceManager::audioDeviceIOCallbackInternal` checks cached `currentCpuUsage` against a default0.98 threshold. Above it, the callback clears output, skips active-context processing and lowers the cached value to at most0.9. A later processing callback refreshes that value from JUCE's filtered device load. JUCE's `AudioProcessLoadMeasurer` smooths callback duration with factor0.2 and exposes a load clamped to0..1. One overlong callback can therefore cause several subsequent callbacks to be deliberately muted even when their DSP workload is small.

This mechanism was reproduced before the policy change in `build/native-overload-red/`: a test-only synthetic sibling callback deliberately slept120ms once. Four later callbacks were silent; the sampler render counter stayed unchanged on precisely those callbacks. Intervening render calls took about0.07–0.08ms. This is a proven recovery mechanism, not proof that the previously untraced silent block or every user-reported stutter had this cause.

VibeRa now sets the engine's CPU-muting threshold to the maximum finite double on the control thread during construction. Cached CPU/xrun measurements remain available, but every callback continues DSP/MIDI rather than adding whole muted recovery blocks based on an older meter value. No larger buffer, playback mute or stop/restart was introduced; the policy is configured outside callbacks and adds no callback allocation or wait. The original overrun remains an overrun; physical drivers may still drop late output. Existing upstream callback locks and provider allocation paths retain separate audit obligations.

`CallbackOverloadRecoveryTests.h` injects that deliberate stall only in the test runner, never the application DSP or a physical driver. After repair, stopped/Pattern/Song each exercise cached load>0.98 and produce zero skipped sampler calls/zero added silent blocks. The injected120.3171/120.3720/121.0204ms measurements are deliberately failed deadlines, not normal performance results. Exact focused evidence: `build/native-recovery-sampler-pass/overload-recovery*.{txt,csv}` and owned process/source receipt. Ordinary413callbacks per mode in that same focused run have maxima0.1946/0.2722/0.1988ms and zero measured overruns. Additional ordinary failure-prefix CSVs now retain engine CPU before/after and device CPU after the callback, outside its measured duration.

## Rollback retains effect ownership and pending edits

The new SDK regression leaves an acknowledged original-worker edit unconsumed, prepares a new worker with a distinct but equivalent XML descriptor, then fails the replacement graph on a deliberately absent sample. It checks the retained Edit/context/device/transport/worker and then the pending edit notification in both Pattern and Song modes.

The first fixture had reversed manual-request value/generation arguments; validation refused it before the intended scenario. That fixture failure is retained separately at `build/native-rollback-red/`. Corrected fixture execution against original product code crashed with0xC0000005 (`build/native-rollback-corrected-red/`). An owned debugger helper, using local public symbols only, confirmed this stack at the fault:

`AutomatableEditItem` destruction → `Plugin` destruction → `RemoteEffect` destruction → effect map assignment → `AudioEngine::rebuild`.

The temporary Edit had already been destroyed when a newly prepared effect's retained global map reference was released during rollback. `build/native-rollback-stack/` preserves the native stack and source/hash records. Obsolete baseline executable/PDB/worker/fixture copies were removed under the single-folder policy; source history and concise diagnostics remain. Only public-symbol frames at the relevant destruction/map chain are treated as named evidence; nearest-symbol labels for optimized unrelated caller frames do not establish their source identity. No user application was attached, no symbol server contacted, and no system debugger configuration changed.

New effect references now remain in a local projection map declared after the owning temporary Edit. Failure releases them before Edit destruction; success commits the complete map only after graph preparation succeeds. With lifetime alone corrected, the test reached the intended second failure: original pending edit=0 (`build/native-lifetime-fixed-observation-red/`). The rebuild transaction now also snapshots/restores `observedParameterRevisions`, alongside its old hosts/effects/errors. The repaired test preserves the original edit, consumes it exactly once, survives control-thread reclamation and recovers the valid project with the same worker. Focused SDK suite passes180153 assertions; `build/native-recovery-parameter-pass/` contains both-mode report and source/process receipts. This fixture is an actual original native VST3 through the production worker; it is not installed third-party compatibility or listening evidence.
