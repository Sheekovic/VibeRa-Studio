# Playback-safe sample preview

## Implemented development behavior

Selecting supported audio in the Browser now auditions while stopped or during Pattern/Song playback. It does not make a Channel, edit the project, select another instrument, seek/restart the main transport, or rebuild the graph. Browser Stop preview and stable customizable browser.stopPreview cancel only audition; global Stop cancels both. Starting the main transport cancels an existing stopped preview, retaining the previous convention. Original-sound and sampler-window audition callers share the same backend.

Preview plays the original sample rate, up to five seconds by default, at adjustable 0-100% gain (default 70%) with short start/end envelopes. Full sample removes the five-second cutoff for supported samples. The prepared sample is stereo; mono device output averages it, and stereo uses the first two outputs. Linear resampling follows device rate. Other output channels receive no preview. Preview bypasses the project Mixer and is excluded from offline export. These are explicit current limitations: no routing/loop controls, tempo/key sync or crossfade on replacement/Stop. Stop/replacement can cut the audition itself; there is no claim of click-free listening quality. SampleCache retains its existing readable-sample limit of 30 seconds. No FL assets or recovered code were used.

## Ownership and callback boundaries

The decoder thread prepares/validates through its SampleCache; the control thread publishes into four fixed slots. Free/retired slots can release their shared sample ownership only on that thread. Pending slots may be coalesced under rapid selection. The callback atomically acquires ready slots, retains exclusive playing ownership, renders borrowed immutable PCM and retires by flag. A monotonically ordered Stop request cancels earlier queued/playing selections. No callback shared_ptr copies/resets, heap allocation, blocking lock/wait, filesystem operation, UI call or sample destruction occurs in SamplePreview. Two bounded producer passes report busy instead of waiting. Callback acquisition scans four slots, and DSP uses constant per-frame work.

The lane registers once with JUCE's device manager at engine construction, not on selection. Shutdown removes/quiesces its callback before slot ownership is destroyed. Device lifecycle callbacks set output rate and retire active playback without destroying PCM in DSP. Device changes can end the current audition; seamless continuation/reconnect is unqualified.

This is not a complete upstream callback audit. Pinned JUCE AudioDeviceManager still locks dispatch and calls tempBuffer.setSize before summing callbacks; Tracktion retains previously documented locks. Normal selections do not add/remove callbacks or change device buffer size. First-use/sample-rate/buffer changes may have upstream allocation. Decoder/cache filesystem work remains on the message thread, so large/cold/network files can stall UI even though the audio lane is independent. Background decode/cancellation and large-library responsiveness are next work.

## Asynchronous decoder follow-up (2026-10-12)

This supersedes the earlier first-load-on-UI limitation for audition. Browser file selection, original-sound clicks and sampler-window Preview now call requestAudition; a lazy owned worker decodes and validates with its own 128 MiB SampleCache. The ordinary UI timer polls completion and publishes prepared ownership into the existing four-slot DSP lane. The synchronous audition API remains for controlled verification; no current source UI caller uses it. Channel creation/replacement still has its existing separate preparation path and is not claimed asynchronous by this change.

There is one queued newest request and one in-flight decoder operation, not an unbounded job list. Generations prevent cancelled/replaced completions from playing or reporting stale errors. Stop preview/global Stop cancel queue/completion before stopping DSP. Repeated sample selections reuse immutable decoded data in the worker's own cache; it does not concurrently access the message-thread project cache. Short control/decoder handoff locking never occurs in DSP, and file decoding runs outside that lock. Decoder exceptions become errors and the worker survives; missing-file errors reach the UI status through the normal timer. The worker starts only on first request, reports startup failure, and shutdown signals/wakes/joins it without unsafe forced termination.

Cancellation discards stale output; it does not abort an in-flight filesystem read. A slow/disconnected network read may delay a newer request and safe shutdown may wait for that read. Existing Browser metadata checks/directory operations are not proven nonblocking on network volumes. Background project-sample preparation, abortable reads/bounded shutdown, search indexing, preview waveform/volume/full-length controls and human listening remain open. This is a concrete audition improvement, not a complete UI/filesystem responsiveness claim.
