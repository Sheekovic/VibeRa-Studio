## Implementation in development0.0.25

Settings > Controllers provides a separate control input/output, Launchkey connection/preset, a scrollable mapping list, Add/Remove/Apply, MIDI Learn/Cancel, an enabled flag, source port/channel/type/number, held modifier layers, parameter range, pickup and banked Mixer target. Existing Settings > MIDI performance input remains independent.

The original mapping engine supports CC, notes, program changes, pitch bend and MIDI Start/Stop/Continue. Buttons invoke the shared keyboard/UI action dispatcher; continuous mappings invoke supported canonical parameters. User macros remain canonical document operations. MIDI Learn captures a source without executing the chosen action. Layer0 is normal; a mappable held control activates Layers1-3. Unsupported parameter/relative combinations and conflicting active links reject rather than executing twice. Fresh drafts are disabled until explicitly applied/enabled or successfully learned.

MK3 preset: Play/Stop/Record arm/Metronome/Undo, Capture-score/Quantize, previous/next Mixer bank, eight banked insert faders, independent Master fader and eight banked pan pots. Session pads cover editors, instrument opening, tiling, clipboard and score/clip operations. Pad16 holds Layer1 for additional project/pattern/layout commands. This software modifier is distinct from the keyboard's hardware Shift/mode controls. The partial final bank has Insert17 only; remaining slots have no insert and report that fact.

Mixer pan/mute have canonical commands using existing model/DSP fields. MIDI fader/pan updates must preserve active note capture; they do not implicitly finish a take. Controller presets and mappings use an atomic separate controller-mappings.json preference file; project schema7 and shortcut/macro files are unchanged. File round trips/invalid input must be verified, not assumed.

## Device and threading boundaries

Novation's [official MK3 programmer guide](https://fael-downloads-prod.focusrite.com/customer/prod/downloads/launchkey_mk3_programmer_s_reference_guide_v1_en.pdf) documents separate performance/DAW ports, DAW-mode messages, CC and Session-pad indices. The PDF was opened as text and its actual pages5/6/8/9/10 diagrams rendered/opened locally. No vendor code, artwork, firmware or custom-mode presets were imported. Generic Learn remains available for other devices.

The hardware input callback only parses short messages, consults atomic masks and publishes into bounded queues. Commands, file persistence and MIDI output run on the message thread. Each source port has its own producer/queue. Generation tags reject stale queued messages after configuration changes; overflow clears stale commands and modifier state. Held note/pedal ownership stays with its original destination through mapping/retrigger/release changes; panic/reconnect resets ownership by a producer-side generation. Software sampler/typing audition bypasses controller learning.

Opening the configured MK3 DAW output sends documented temporary DAW enable only to an identified MIDIOUT2 LKMK3 endpoint paired with an open control input. Close disables only a mode this instance enabled. Performance/control inputs cannot alias. No keyboard firmware update, global driver change, factory/custom-mode overwrite or unrelated-process termination. Pad/transport LED output is implemented; physical feedback still needs verification.
