## Implemented development foundation

The native left Browser now includes a background-scanned JUCE directory tree, Folder picker, Up, Refresh, case-insensitive file-name filter, folder drops, folder expansion and WAV/AIFF/FLAC/MIDI entries. No personal/reference folders are automatically added. The existing four original sounds and VST3 browser remain accessible. At compact height with an opened library, the original-instrument group folds to give files room; the header manually expands/collapses it. The tree uses remaining vertical space and remains visible above Project information at the checked layouts.

File selection supplies the real drag payload. Current audio selection auditions during stopped, Pattern or Song playback through the prepared asynchronous preview lane. Volume and Full sample controls are implemented with explicit limits in LIVE_SAMPLE_PREVIEW.md; earlier checkpoint evidence below is historical. Context menu/Middle-click send compatible content to the selected Channel; context/new sample and sample double-click create a Channel, preserving the established VibeRa original-sound double-click convention. MIDI uses the existing guarded import path. Audio internal drag still targets Rack; MIDI internal drag can target Rack/Piano and respects import modifiers. Builtin source identifiers are kept out of filesystem path parsing. Unsupported types, audio Playlist clips, external presets and formats are not silently enabled.

Directory enumeration/filter synchronization belongs to JUCE's own background TimeSliceThread and the UI. No Browser work is added to audio callbacks. The filter lifetime outlives its listing; shutdown removes listeners/clears the directory list before stopping the owned thread. Slow/network/large-folder shutdown and stress are unqualified.
